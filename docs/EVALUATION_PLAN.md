# Independent measurement protocol — prepared, not executed

1. Have the billing lead name a concrete recurring agreement/work/invoice mismatch and identify current systems, licensed modules and reporting/configuration already available.
2. Define the supported USD standard RN scope, controlling document precedence, billing calendar, source completeness evidence and stable identity references before obtaining records. Decide whether configuration work solves the problem better.
3. Obtain authorized minimized exports and independent labels from two human reviewers. Reserve a held-out service interval. Disagreements require adjudication, not the app as ground truth.
4. Agree acceptance thresholds before viewing results: precision, recall on represented error types, dollar-weighted misses, evaluated records/minutes, abstention, reviewer minutes, export/mapping/approval/setup burden, usefulness of incremental findings and actual documented correction outcomes. A proposed precision target is not an achieved result.
5. Compare the same input scope with the current manual process and the properly configured incumbent. Count export/preparation/review/rule-maintenance effort, false positives and missed findings. No errors in a small sample means recall is inconclusive.
6. Test a realistic negative set: ambiguous identifiers, unsupported terms, stale/partial invoice sources, duplicated/overlapping snapshots, late work entry, mixed-rate aggregates, signed credits and competing applicable rules.
7. Deliver a documented go/no-go recommendation. A successful diagnostic may recommend configuration help rather than a recurring product. Collection/recovery remains unknown without payment/remittance evidence.

Current evidence: synthetic fixture/golden tests and app behavior only. No real-data measurement, independent label agreement, commercial acceptance, SLA or certification is claimed.
