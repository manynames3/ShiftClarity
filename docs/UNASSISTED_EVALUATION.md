# First-review acceptance tasks

October 31, 2026. A repeatable customer evaluation protocol, not a claim that a billing manager has passed it.

Use fictional or authorized minimized records in the browser-local evaluator. Keep the controlling agreement and source exports available. Do not upload customer records to the synthetic cloud pilot.

## Task A: first review (target: 15 minutes with prepared exports)

Give the tester only the product URL, the three fictional CSV/Excel files and the controlling rate register. Do not explain mappings or operate the interface for them. Ask them to:

1. Select the work and billing files. Identify the suggested header and verify three sample rows against the originals. Explain which source rows are excluded as report titles.
2. Supply the approved rates, either as a file or by entering the terms. Distinguish agreed bill rates from invoice rates and wage rates.
3. Confirm code meanings and time units. Use dates found in work records, then confirm the actual reporting scope. Choose the source reporting timezone and its cutoff/current-through timestamps.
4. Explain what the completeness declarations establish. Leave an uncertain declaration unchecked rather than guessing.
5. Find the missing allocation and one rate difference. Explain the $460 potential underbilling, $24 potential overbilling and the two records with no estimate. Locate the $25 fee and credit/rebill in the report.
6. Download the Excel report, confirm reviewer notes are off by default and explain why a finding does not establish recovered money.

Record elapsed time, every help request, abandoned step, unclear label and incorrect interpretation. A completion that required coaching is assisted; record it that way. The proposed target is no unexplained blocker, no silent row loss and correct interpretation of findings and exclusions.

## Task B: repeat review (target: five minutes with prepared exports)

Save mapping metadata, refresh and select another fictional period's files. Reuse the mapping, explicitly confirm new codes, dates and declarations, and obtain the new report. Verify records from the prior review were not retained. Measure preparation time separately from reconciliation/review time.

## Task C: deliberate source problems

Use a titled/reordered export, a weekly summary without service dates, a repeated totals row, a duplicate file, an unknown code and an ambiguous date. The tester must either resolve the actual cause or identify the specific report/evidence required. A rejected report is a successful safety outcome only when the tester understands the next action. Never coach them to invent service dates, approval events, hourly units or agreement rates.

## Evidence already available

Automated journeys cover file-first CSV preparation, header/date suggestions, row previews, mappings and their reuse, direct rate entry, local reporting-time conversion and a downloadable report. Regression cases cover totals/repeated headers, privacy, duplicates, unit conflicts, unknown codes, ambiguous dates and DST gaps/repeated times. Existing parser/engine tests retain signed credits, mixed billing scope, precision and incomplete coverage checks.

These are software checks and manual agent inspection. An actual billing user's unassisted success, vendor-certified compatibility and contract-specific accuracy remain unmeasured. Mark acceptance only after observing the intended user and independently checking the expected results.
